# Lira Reader

Ридер использует нативные Flutter-виджеты для EPUB и `pdfrx` для PDF. WebView-реализация и её зависимости удалены. Это не браузерный EPUB/CSS-движок и не извлечение PDF в EPUB-подобный текст.

## Общий экран

`ReaderScreen` загружает локальный файл и выбирает реализацию `BookReaderEngine`:

- `EpubBookReaderEngine` → `packages/epub_engine`;
- `PdfBookReaderEngine` → `packages/pdf_engine`.

Экран отвечает за панели, оглавление, настройки, сохранение выделений/заметок, закладок и прогресса. Движок отвечает за содержимое, навигацию и координаты выделенного текста. `BookLocation.locator` — непрозрачная для общего интерфейса строка.

Начальная позиция применяется один раз при открытии книги. Сохранение прогресса не является командой повторной навигации. Переходы из оглавления, списка выделений и закладок идут через `goToLocation`.

Прогресс-индикатор обновляется из событий движка. Записи в Drift объединяются с задержкой в одну секунду и сериализуются: завершение старой записи не может потерять новую позицию. `flush()` сохраняет последнее ожидающее значение при закрытии, смене книги, уходе приложения в фон и disposal. Кнопка возврата ожидает запись и проверяет исходный route, чтобы не закрыть предыдущий экран при одновременном системном Back. Ошибка записи не заменяет уже открытое содержимое экраном загрузки.

Невалидный EPUB/PDF возвращает ошибку загрузки, а не подставную «главу с ошибкой».

### Закладки, заметки и панели

Кнопка закладки в верхней панели сохраняет последнее фактически показанное место из события движка, а не начальный locator или выделенный диапазон. Заполненная иконка позволяет удалить закладку текущего места. Общая панель пометок разделена на «Выделения» и «Закладки»: выбор строки переходит к сохранённому locator, отдельная кнопка удаляет запись.

Текущая закладка EPUB v2 определяется в пределах ±400 UTF-16 символов одного spine-документа, поэтому небольшая прокрутка не превращает её в новую точку. Точное совпадение имеет приоритет, иначе выбирается ближайшая закладка. Legacy locators сопоставляются только точно; для PDF областью служит одна страница. Это правило меняет только состояние кнопки и выбор записи для удаления: сохранённый locator и точность перехода остаются прежними.

Закладки EPUB/PDF хранятся в Drift (`Bookmarks`, схема БД v3): книга, непрозрачный locator, процент и время создания. Уникальность `(bookId, location)` исключает дубли одного места; удаление книги атомарно очищает её закладки. Миграция v2 → v3 создаёт новую таблицу без изменения существующих книг, прогресса, выделений и заметок.

`ReaderScreen` не уменьшает viewport книги при появлении клавиатуры: keyboard insets обрабатывает сам диалог заметки. Это сохраняет пагинацию и прокрутку за открытым редактором в обоих режимах. Редактор существующей заметки ждёт сохранения, не теряет введённый текст при ошибке и освобождает controller только при disposal диалога.

Верхняя и нижняя панели закреплены у краёв и используют `AnimatedSlide` на собственную высоту. Скрытие воспроизводит обратную кривую появления; отключённые анимации учитываются через `AppMotion`. Показ панелей не меняет layout содержимого.

На Android системные status/navigation bars следуют за панелями ридера: скрыты при чтении, показаны вместе с top/bottom bars. Переход выполняется через native `WindowInsetsController` на API 30+ (immersive flags на старых Android), без отключения edge-to-edge или снижения target SDK. Возврат из фона и закрытие клавиатуры восстанавливают нужный режим; при ошибке загрузки и выходе из ридера системные панели показываются. Другие платформы не меняются.


## EPUB pipeline

```text
ZIP → container.xml → OPF manifest/spine
                         ├── главы в порядке spine
                         ├── отдельное NCX / EPUB3 nav оглавление
                         └── изображения, обложка и локальные CSS
XHTML → общий обход XML/HTML + CSS cascade → TextBlock / ImageBlock / TableBlock / DividerBlock
                   → EpubNativeView
```

### Содержимое

- Порядок чтения задаёт OPF spine, не порядок manifest или TOC.
- Несколько TOC anchors на один документ не дублируют его текст.
- Оглавление берётся из EPUB3 nav с сохранением названий и вложенности; отсутствующая, повреждённая или не содержащая переходов nav-навигация уступает NCX. Только при отсутствии оглавления используется список spine-документов.
- Кириллические и смешанные Unicode/percent-encoded fragments нормализуются до декодирования: одно такое имя якоря не должно приводить к потере всего оглавления.
- Имена вроде `stockholm.xhtml`, `cover.xhtml` или `copyright.xhtml` не являются причиной выбрасывать spine-документ.
- Отсутствующий/пустой обязательный HTML-документ spine вызывает явную ошибку, а не частично успешное чтение.
- При отсутствующем/пустом spine сохраняется восстановление по manifest без явного nav-документа.
- XML/XHTML читается как UTF-8 или UTF-16 LE/BE; повреждённые последовательности не заменяются молча символами `�`.

Изображения разрешаются по полному пути относительно документа, с однократным декодированием URI и удалением query/fragment. Одинаковые basename в разных каталогах не смешиваются; буквальные `%` в ZIP-именах сохраняются. Картинки внутри абзацев и списков не теряются. Поддерживаются SVG-обложки с растровым `<image>` и самостоятельные SVG с вложенными локальными `<image>`; векторные вложения встраиваются с сохранением viewport и изоляцией идентификаторов. Сетевые изображения не загружаются.

### CSS, списки и таблицы

- Сохраняются отдельные абзацы цитат, явные `<br>` и вложенность списков. `<ul>` использует маркеры для всех пунктов; `<ol>` учитывает `start`, `reversed`, `type` и `li value`.
- Локальные linked/inline CSS и `@import` образуют cascade с specificity, порядком правил и `!important`. Поддерживаются tag/class/id, universal, descendant и child selectors; относительный размер/начертание/цвет текста, decoration, text-align, super/sub, display/visibility и неотрицательные отступы абзацев без процентов.
- Семейство шрифта и межстрочный интервал читателя имеют приоритет над авторскими `font-family` и `line-height`, включая `!important`. Абсолютные авторские размеры масштабируются относительно пользовательского размера с базой CSS 16 px; пропорции заголовков и сносок сохраняются. Web fonts, сложный browser layout, floats, CSS grid, отрицательные/процентные margins и условные media queries не реализуются.
- Таблицы сохраняют строки, равные по ширине колонки, `rowspan`/`colspan`, заголовки, вложенный текст и картинки. `rowspan` ограничен своей группой строк; caption и ячейки сохраняют anchors.
- В горизонтальном режиме длинная таблица разбивается между группами строк без разрыва объединённой ячейки. Строка выше viewport прокручивается внутри своей страницы; позиция этой прокрутки участвует в сохранении и reflow.
- Выделение, highlights и ссылки внутри таблицы используют порядок текста исходного XHTML, независимо от расположения ячеек на экране.


### Настройки чтения

Панель показывает названия и значения четырёх регуляторов: размер шрифта 12–32, межстрочный интервал 1–2.5×, боковые поля и яркость. На телефонах поля остаются в диапазоне 8–64 logical px; на десктопах и больших планшетах доступны 8–240. В развороте поля применяются отдельно к каждой странице. Эффективное значение ограничено шириной страницы, оставляя не менее 160 px текста (или всю доступную ширину на более узком viewport); сохранённая настройка при resize не переписывается.

Для чтения локально поставляются Inter, Lora, Literata, Source Serif 4, PT Serif, Noto Serif, Merriweather, Roboto Slab, PT Sans, Noto Sans и Roboto. Все семейства содержат латиницу и кириллицу; настоящие курсивные варианты включены, кроме upright-only Roboto Slab. Файлы и лицензии находятся в `assets/fonts`, каталог — `reader_font_catalog.dart`. Сеть для выбора шрифта не нужна; прежние системные/generic настройки и значения по умолчанию не сбрасываются.

### Отображение и позиция

Вертикальный режим использует `ScrollablePositionedList` с главами и точным размещением по геометрии `RenderParagraph`. Горизонтальный режим измеряет блоки через `TextPainter`, разбивает их на страницы и показывает одну страницу или разворот. Перелистывание рисуется нативным `Canvas`: текст и изображения изгибаются вместе с листом, оборот и тени учитывают цвет бумаги; в развороте лист переворачивается вокруг центрального корешка.

Лист следует за горизонтальным движением пальца. Отпускание после 28% ширины viewport или быстрый жест от 600 logical px/s завершает перелистывание; короткий жест, движение обратно и отмена указателя возвращают лист. Тапы по краям, стрелки/Page Up/Page Down и трекпад запускают ту же анимацию. Системное уменьшение анимации переключает страницы без эффекта.

На начало жеста создаётся снимок текущей страницы; для разворота после layout также снимается целевой разворот, чтобы напечатать правильный текст на обороте листа. Pixel ratio снимков ограничен 2, повторного захвата и перестройки текста на кадрах анимации нет. Отменённый жест не меняет сохранённую позицию; новая позиция публикуется только после завершения перелистывания. Переход из оглавления, reflow, смена режима/книги и resize отменяют незавершённый лист. Горизонтальный drag recognizer находится внутри `SelectionArea`, сохраняя native long-press/мышиное выделение и вертикальную прокрутку высоких таблиц.

Проверка `RenderObject.debugNeedsPaint` перед снимком выполняется только при `kDebugMode`: в profile/release этот getter сам выбрасывает исключение. Перелистывание нужно проверять запуском release/profile-сборки; widget-тесты с включёнными asserts этот класс ошибок не обнаруживают.

Перед изменением шрифта, интервала, отступов, размера viewport или режима сохраняется логическая позиция. Новый layout сразу начинается с измеренной главы и текстового смещения, без промежуточного показа обложки или публикации позиции начала книги. Измерение и отрисовка используют одинаковые параметры текста и полей; кэш пагинации учитывает эффективные отступы. Размер страницы не является сохранённым местом чтения. При переходе на правую страницу разворота сохраняется именно целевой текст, а не глава левой страницы.

`EpubCfi` — историческое имя собственной JSON-модели, **не стандартная EPUB CFI-строка**:

- `s`: индекс документа;
- `a`: XHTML id / named anchor;
- `c`: символьная координата;
- `f`: доля главы;
- `so` / `eo`: диапазон выделения, конец не включён;
- `bo` / `bf`: старые пиксельные/общекнижные координаты;
- `v: 2`: `c` задан точно в UTF-16 координатах разобранного содержимого `XhtmlParser`, включая генерируемые маркеры блоков.

Без `v:2` запись остаётся legacy: при восстановлении учитываются anchor, диапазон выделения и прежние `f` / HTML-based `c`; пиксельные записи также читаются. Прочтение JSON само по себе не меняет его версию. После фактического восстановления native renderer публикует точную v2-позицию. Миграция схемы БД не требуется.

Старые индексы из книги, которую прежний парсер читал не полностью или не по spine, не всегда однозначно сопоставимы исправленному содержимому: в старой записи нет идентификатора исходного документа. Совместимость формата не означает восстановления отсутствовавшей информации.

Исправление ранее потерянных inline-картинок и ошибочных маркеров списков также меняет координаты текста в затронутой главе. Старые точные позиции и выделения после таких элементов могут сместиться: JSON locator не хранит версию парсинга или исходную цитату для однозначного пересчёта. Формат v2 остаётся читаемым; автоматического пересчёта этих записей нет.

### Выделения и ссылки

Выделения адресуются диапазонами текста. Пересечения и вложенные диапазоны меняют фон spans, но не сам текст. Selection notifier и render keys принадлежат смонтированному scope, а не общему индексу главы: indexed jump может временно держать две копии главы.

Внутренние ссылки и TOC fragments разрешаются относительно документа с нормализацией percent-encoded путей. Hit-test использует геометрию полного видимого диапазона ссылки, включая emoji и переносы. Внешние HTTP(S)-ссылки открываются через `url_launcher`.

## PDF pipeline

`pdfrx` сохраняет исходную PDF-вёрстку. Controller и document reference стабильны в пределах открытой книги; обновление прогресса, настроек или highlights не создаёт новый viewer.

Область PDF центрируется и ограничена шириной 800 logical px, как одиночная страница EPUB. При расширении окна книга не растягивается на весь монитор; на более узком viewport используется вся доступная ширина. Это ограничение стандартной области чтения, а не запрет увеличения: native zoom и перемещение увеличенной страницы остаются доступны.

- Старый locator прогресса — строковый номер страницы, начиная с 1.
- TOC и обычные PDF destinations переходят через controller; номера страниц ограничиваются документом.
- Выделение берётся из реального `onTextSelectionChange`, а не из отдельного поиска совпавшей строки.
- `PdfReaderLocation` хранит версию `pdf:1`, страницы, диапазоны извлечённого текста и геометрию фрагментов в PDF-координатах (Y направлен вверх). Zoom и размер окна не меняют сохранённые прямоугольники.
- Highlights рисуются `pagePaintCallbacks`; удаление перестраивает overlay без переоткрытия файла.
- Возврат к highlight центрирует его прямоугольник без увеличения текущего zoom. Если выделение не помещается, масштаб уменьшается ровно до необходимого; переход не превращает одну фразу в текст на весь экран.
- Пустое native selection очищает панель Lira; успешные Copy/Highlight снимают native focus/selection.
- Reader tap наблюдается через raw pointer events без competing tap recognizer. Single tap ожидает окно double-click; drag, long-press и multi-click не превращаются в переключение панелей.
- Жесты pan/pinch трекпада обрабатываются также над выделяемым текстом, который может закрывать native recognizer `pdfrx`. Дополнительный recognizer принимает только `PointerDeviceKind.trackpad`, не конкурируя с выделением мышью или touch-жестами. Колесо над боковыми полями передаётся viewer один раз; над самой страницей остаётся native обработка.
- Внутренние PDF links обрабатываются через destinations, внешние HTTP(S) — через `url_launcher`.

В `pdfrx 1.3.5` нулевая высота/ширина прямоугольника edge selection ошибочно обнуляет непустое выделение. PDF-local `SelectionContainerDelegate` добавляет такому диапазону толщину 0.001 logical px перед передачей native selectable. Collapsed caret не изменяется; сохранённые ranges/fragment rectangles по-прежнему вычисляет сам `pdfrx`.

`pdfrx 1.3.5` не реализует paragraph selection для triple-click. Lira не подменяет его одиночным reader tap.

## Проверки

Из корня проекта:

```bash
flutter pub get
flutter test test packages/epub_engine/test packages/pdf_engine/test
```

Тесты с настоящим PDFium требуют `PDFIUM_PATH`, иначе они явно пропускаются. На macOS можно использовать framework после локальной debug-сборки:

```bash
flutter build macos --debug
PDFIUM_PATH="$PWD/build/macos/Build/Products/Debug/pdfrx/pdfrx.framework/pdfrx" \
  flutter test --no-pub test packages/epub_engine/test packages/pdf_engine/test
```

Регрессии проверяют порядок и целостность EPUB, кодировки, вложенное nav/NCX-оглавление с Unicode-якорями и fallback, reflow/позиции, Unicode-границы пагинации, перекрытия highlights, ссылки, закрытие/повторное открытие, гонки сохранения и реальные PDF selection/геометрию/навигацию/перерисовку. Отдельно проверяются keyboard insets редактора заметок в обоих режимах, обратное скрытие панелей, сохранение/переход/удаление закладок, границы их области и удаление после небольшой прокрутки, миграция v2 → v3 и ошибки записи пометок.

Для диагностики содержимого EPUB без Flutter UI:

```bash
dart --packages=.dart_tool/package_config.json \
  packages/epub_engine/bin/debug_epub_parser.dart path/to/book.epub
```

Проверка на реальных Android/iOS устройствах и profile-замеры больших книг остаются отдельными от desktop regression tests. Общий performance roadmap находится в `PERF.md`.
